## The stages (one per chat, so each is small enough to finish and test)
1. **Stage 1 - DONE (v0.814.0):** voice + search + browser + history + colours + screen 2 + Bibles + web version + media/slides/countdown in the web version.
2. **Stage 2 - DONE (v0.815.0, see `STAGE2-SPEC.md`):** Desktop media and slides: pictures, video, slides, lyrics, backgrounds, timers in the Rust app (video needs a decoder library; we pick one with a permissive licence). *Why first:* it is what stops a church needing a second program.
3. **Stage 3 - Accounts and money:** Supabase login, Stripe subscription, signed tickets, device limit, connect `license.rs` to the server, free-mode fallback. *Why:* nothing is a business until it can charge.
4. **Stage 4 - Bible licences:** bring-your-own API.Bible key, aggregator quote, publisher emails, add-on Bibles, two versions on screen. *Why:* NKJV/NIV/AMP are what churches ask for.
5. **Stage 5 - Live-event extras:** preacher stage display, NDI/Syphon, live captions, verse paging, confidence monitor, lexicon editor, more languages. *Why:* the "wow" features for bigger churches.
6. **Stage 6 - Make it a real product:** installer, code signing and notarisation (Apple), auto-update, crash reports, accessibility, first-run tour, sample service, a 2-hour soak test with a real sermon. *Why:* trust.
7. **Stage 7 - Teams:** cloud library, roles, multi-campus, import/export, analytics. *Why:* bigger churches pay more.
